AIOrchestrator Built
Application/Services/AIOrchestrator/
Decides which path a chat takes — the iPad's only routing surface. After cutover the only live route is "to the FalcoMain pipeline via the n8n forwarder". Direct cloud-LLM paths (the legacy openAI / anthropicAI / perplexity cases) are removed in Phase 4.
NetworkService — Trace-ID injection Planned
Network/TraceId.swift (new) + existing API.swift
Generates a UUIDv7 at the moment the user taps send. Attaches it as X-Falconium-Trace-Id on every outgoing chat request. The trace ID flows iPad → forwarder → Django → all logs → Sentry → response body.
LiveMessageWriter Built
Application/Services/LiveMessageWriter.swift
Streams response chunks into the chat view, persists to local store. Trace ID and run ID echoed back from the response are attached to the message record.
Diagnostic affordances Planned
ConversationView · Settings
  • Long-press any chat bubble → Copy diagnostic places trace ID on clipboard
  • Settings → Send debug bundle emails the rolling log + last 24h Sentry breadcrumbs to Ilya
  • Pasting a trace ID into backend.falconium.ai/admin/run/<id> shows the full pipeline run
Logger service Partial — verbose mode pending
Application/Services/Logger/
Existing logger raised to verbose for the single-user phase. Writes to:
  • Sentry breadcrumbs — every state change, every network call
  • Rolling local file in app Documents — 7-day window, 100 MB cap
  • NSLog / OSLog for Xcode console
Wire contract preserved: the iPad continues to call https://backend.falconium.ai/n8n/webhook/df5cb261-…. No app version bump, no TestFlight push required for cutover. The change happens behind that URL, not in front of it.
Seams

Future Layers — designed-in surfaces ready to activate

UI seams that the iPad reserves space for, paired with backend seams
FalcoJudge response surface
ConversationView — paired with backend §6
When FalcoJudge activates and produces a counter-argument, verification note, or confidence score, the iPad needs a place to render it inline. Day one: response is presented as-is. Future: small badge under the response with "view verification" affordance.
On-device speech pipeline (full)
WhisperKitService + FluidAudio + PocketTTS
STT and TTS already on-device. Speaker diarisation via FluidAudio is partly wired. The seam is the last mile: ElevenLabs cloud TTS removed entirely from the critical path (cleanup brief), Replicate kept as STT fallback for two releases, then removed.
Edge orchestrator — Llama 3.5
LLM/ — apps/llm runtime · planned
Long-term: an on-device classifier and lightweight orchestrator that runs before any cloud call leaves the iPad. The current architecture has the n8n forwarder doing this; the edge orchestrator absorbs that role over time, keeping the conversation loop entirely on-device for low-stakes turns.
Anonymisation preview
ConversationView — paired with backend §9
When the anonymisation chokepoint activates, the iPad shows an unobtrusive indicator that the message was anonymised before leaving the device, and lets the user inspect the redactions. Day one: pass-through, no UI surface.
Financial Observatory morning surface
Modules/Home/Contents/MorningObservations — planned · §15
The user-facing side of nightly contemplation: a morning observation list with full provenance and accept/dismiss/annotate controls. Specified in v1.1 of the architecture document; promotion to MVP scope is a discrete decision.
Settings → Secrets entry
Modules/Settings — webview onto backend admin
A simple in-app entry point to backend.falconium.ai/admin/secrets/ for key rotation. Optional — Ilya can always reach the same form from a browser. Provides a single place to manage every credential without touching code.

LLM & on-device inference

LLM module Partial

Network & data models

API.swift Built
Network/API/API.swift
Single endpoint enum. Every request type is a case here. Cases used by the new flow: sendUserMessage (chat), conversations, messages, transcribeAudio, uploadFile, documents, etc. Cases removed in Phase 4: llmAnswer and the direct provider cases.
URLs.swift · AppKeys.swift Partial — keys removed Phase 0
lockkkk/Application/Constants/
URL constants and (currently) hardcoded API keys. After Phase 0:
  • Keys come from xcconfig at build time, sourced from SSM via Fastlane
  • Singularis URL fallbacks replaced with backend.falconium.ai (cleanup brief item 1)
API Models Built

Codable request and response models for every backend endpoint. Including SendUserMessageHttpBody, SendUserMessageResponse, plus models for AI responses (AnthropicResponse, OpenAIResponse, PerplexityResponse, LLMAnswer) — the latter set is retired with the direct-provider paths.
